# 仕事

仕事で調べたことを残すフォルダ。

## 書いてよいこと・書かないこと

Records は GitHub の公開リポジトリなので、だれでも読める。

- 書く：言語・フレームワーク・ミドルウェアの仕様や挙動、エラーの原因と直し方、設計の一般的な考え方など、どの職場でも通じる内容
- 書かない：会社名・顧客名・案件名、社内システムの構成や設定値、社内のソースコード、URL・IPアドレス・認証情報、社内資料の写し

社内の事情に触れないと説明できないときは「ある業務システムで」のようにぼかすか、Records の外に置く。

## 置き方

- テーマごとにフォルダを作る（例：`Laravel/`、`MySQL/`、`AWS/`）
- 1つの調べものを1ファイルにし、ファイル名は調べた内容が分かるものにする（例：`Eloquentのchunkとcursorの違い.md`）
- ファイルの冒頭は次の形にする

```markdown
# 題名

調査日：YYYY-MM-DD
きっかけ：なぜ調べたか（社内の事情はぼかす）

## 結論

## 調べたこと

## 参考
```
