# Civ7 ゲームログの調査

調査日：2026-11-02
対象：Civilization VII（このフォルダ名は Civ6 のまま）

照合の詳細：[20261102_T001-T014_照合.md](20261102_T001-T014_照合.md)

---

## 1. 結論

* ゲームは設定を変えなくても、毎ターンの出来事をログファイルに書き出している
* 記録していたゲーム（20261102。やり直す前のゲーム4）のT1〜T14では、制作ノートの「ゲームで起きたこと」のうち、ユニットの移動以外はほぼすべてログから取れた
* 発見イベントの本文と選んだ選択肢、独立勢力の名前は、ログとゲーム本体のテキストを突き合わせれば取れる

---

## 2. ログの場所と性質

* 場所：`%LOCALAPPDATA%\Firaxis Games\Sid Meier's Civilization VII\Logs`
  * 設定ファイル（`AppOptions.txt`、`UserOptions.txt`）は、ひとつ上のフォルダにある
  * セーブは `ドキュメント\My Games\Sid Meier's Civilization VII\Saves`
* ゲーム起動中は、エクスプローラーなどで0バイトに見えることがある。書き込み中でサイズの表示が更新されていないだけで、中身はある
* ゲームを起動するたびに Logs フォルダは作り直される。残したいログは、次に起動する前にコピーする
* 1回の起動中に遊んだゲームは、すべて同じファイルに続けて書かれる。ターン番号が戻るところが区切りになる
  * 新しいゲームを始めたとき、セーブを読み込んだとき：ターンが1（または読み込んだターン）に戻る
  * 時代が変わったとき（古代→探検）：ターンが1に戻る。`Historian.csv` の時代の列で見分けられる

## 3. 記録に使えるファイル

## 4. 補って読む方法

### 人間プレイヤー

* `Metaprogression.log` の `Campaign challenge 'CHALLENGE_<指導者>_...' complete!` に出る指導者が自分
* 今日のゲームでは、どれもプレイヤー0が自分だった

### 発見イベントの本文と選択肢

* `NarrativeStories.log` の `Player 0, Coord x: 63, y: 37, Requirements met for story DISCOVERY_21002A` のような行を使う
* IDの末尾の文字：A＝発生、B／C＝選んだ選択肢、D＝その後の結果（ない場合もある）
* 本文はゲーム本体の `C:\Program Files (x86)\Steam\steamapps\common\Sid Meier's Civilization VII\Base\modules\age-antiquity\l10n\ja_JP_Text.xml` にある
  * `LOC_DISCOVERY_21002A_STORYTITLE`（題）、`..._A_COMPLETION`（本文）、`..._B_NAME`（選択肢）、`..._D_COMPLETION`（結果）、`..._D_DESCRIPTION`（効果）
  * 本文中の `{1_Homeland_Independent}` などは、ゲーム画面では独立勢力の名前などに置き換わる。何に置き換わったかはログからは分からない
  * 探検の時代以降の本文は、`age-exploration` などの同じ場所にあると思われる（未確認）

### 独立勢力の名前

* `Game_Gossip.csv` の `MEET_INDEPENDENT` では、名前が空欄になっている
* `Independents.csv` の `CREATE TRIBE` 行と座標を突き合わせると、種類（例：`INDEPENDENT_ANTIQUITY_44`）が分かる
* 同じ XML の `LOC_INDEPENDENT_ANTIQUITY_44_MAJOR_NAME` が名前（セレウキア）、`..._MINOR_NAME` が民族名（セレウコス）
* `DiplomacySummary.csv` の接触（Met）に出るプレイヤー番号は、`CREATE TRIBE 18` の番号と同じ

## 5. ログに残らないこと・分からないこと

* ユニットの移動（河を渡った、岸から対岸を見た、どこへ向かったか）
* 発見イベントを起こさず、見つけただけの集落
* 選択肢の効果の量（何がどれだけ得られたか）、集落が地図に残ったか
* 独立勢力との「接触」は2種類あり、ターンが食い違うことがある。`DiplomacySummary.csv` の Met と、`Game_Gossip.csv` の `MEET_INDEPENDENT` である（例：カルタゴは Met がT6、`MEET_INDEPENDENT` がT11）。それぞれが何を意味するかは未確認
* `NarrativeStories.log` にはターンが入らないため、同じ起動中に遊んだ別のゲームで、同じ座標に起きた発見の行も拾ってしまう（例：20261102のT14、(51,21) で2つのストーリーが出た。片方は前のゲームのT75のものと思われる）
* `DiplomacyDeals.log` は、ターンだけではゲームの区切りが決まらない（ゲームが変わるたびに取引番号が1に戻るが、取引のないゲームは見分けられない）。別のゲームの取引を取り違えるおそれがあるので、行動記録には使っていない
* 時代の最後のターンは、自国の分だけ `Player_Stats.csv` に書かれて時代が終わることがある。他の文明と比べるときは、その1つ前のターンを使う
* プレイヤー番号63（20261102のT2に接触）が何なのかは不明
* `UserOptions.txt` に `GameHistoryLogLevel`（ゲーム履歴のログ）の設定がある。有効にしたときに何が出るかは未確認

## 7. スクリプト

* [スクリプト/current_game.py](スクリプト/current_game.py)：Logs の最後のゲームから、指定したプレイヤーの出来事をターンごとに書き出す
  * 使い方：`python current_game.py "<Logsフォルダ>" 出力.txt 0`（最後の引数はプレイヤー番号）
  * 発見イベントの本文と独立勢力の名前は、まだ差し込まない
* [スクリプト/age_record.py](スクリプト/age_record.py)：1つの時代の出来事を、まとめとターンごとの Markdown に書き出す。発見イベントの本文、独立勢力の名前、ユニットや建物の和名を差し込む
  * 使い方：`python age_record.py "<Logsフォルダ>" 出力.md --player 0 --segment -2`
  * `--segment` は、Game_Gossip.csv をターンが戻る位置で区切ったときの何番目を使うか。次の時代に入った直後なら -2 が終わった時代
  * Logs はゲームを起動し直すと消えるので、時代が終わったら次に起動する前に実行する
  * 探検の時代以降にも使える（2026-11-03）。2つ目以降の時代は最初の都市を建てないので、文明とプレイヤー番号の対応は、同じゲームの最初の時代までさかのぼって取る。前の時代に建てた都市の名前も使う
  * 近代の時代で増えた出来事（2026-11-03）：遺物の発掘（ARTIFACT_EXTRACTED）、ユニットの解散（DISBANDED_UNIT）、取引の拒否（REJECT_DEAL）、昇格（UNIT_PROMOTION）。都市の占領は Gossip（CONQUER_CITY、URBAN_CONTROL_CHANGED）と DiplomacySummary の City Capture の両方に出るので、DiplomacySummary だけを使う。都市国家の宣戦布告などは「〇〇（都市国家）」と書く。CombatLog の「Unit vs Location」（都心などの区画への攻撃）と「Unit vs Army」（軍隊への攻撃）にも名前をつけ、都市や区画への攻撃には都市の名前を添える
  * レガシー（Player_Legacies.csv）はターンがまばらで、時代の最後のターンまで続かないことがある（近代は T53 が最後）。ターンで時代を合わせると取りこぼすので、コードの時代（LEGACY_AQ／EX／MO）が同じ区切りのうち最新のものを使う
  * 上位のユニット（平安日本の和弓兵のティア2「UNIT_YUMI_2」など）は名前のタグがないので、末尾の数字を外した名前で引く（2026-11-03）
  * いちばん新しいゲームの記録を作るためのスクリプト。あとから古いゲームを新しい Logs で作り直すと、レガシー（時代の印が同じ区切りのうち最新のものを使う）など、まばらなログが新しいゲームのものになることがある。古いゲームの記録は、そのとき作ったものを正とする
  * 勝利は Gossip には出ない。GameCore.log の「Team 0 has won 1 place in a 'VICTORY_〇〇' victory!」と、Metaprogression.log の「CHALLENGE_〈指導者〉_〇〇_VICTORY」で分かる
  * 勝利したターンは Telemetry.log で分かる（2026-11-03）。「SendCampaignStatusTelemetry - statusName: CampaignTurnEnd iCurrentTurn: N」がターンの終わりの時刻、「AgeEnd iCurrentTurn: N」が時代の終わり（近代では勝利）の時刻。ゲーム5は T59 の終わり 03:06:02 → 勝利 03:06:05 → AgeEnd T60 03:06:06 で、作者の言う T60 と合う。ゲーム6は T59 の終わり 18:24:27 → 勝利 18:24:31 → AgeEnd T60 18:24:32。age_record.py は、GameCore.log の勝利と「Player N has been defeated」（滅亡）の時刻を、直後に終わったターンに直して書く。調べる範囲は、その時代に T1 で入った時刻（CampaignEnter iCurrentTurn: 1）から、次に T1 で入る時刻まで。前のゲームの勝利は最後のターンの終わりより後に記録されるので、ターンの終わりでは区切れない
  * 滅んだ文明は、指導者のいる文明だけ名前を書く。都市国家などのプレイヤー番号は名前に結びつかないので、数だけ書く。最後の「各文明」の比べからは、時代の途中で滅んだ文明を外す（前は全員がそろう最後のターンで比べていたので、ゲーム6の近代では T98 で止まっていた）
  * 近代で増えた出来事（ゲーム6）：都市の焼き払い（Gossip の CITY_RAZED）、奪った都市を焼き払わずに残す（OCCUPY_CITY。他国が奪った都市にも出る）。都市の名前と奪う前の持ち主は、その座標の建設・人口・占領の行から引く（都市は何度も持ち主が変わることがある）
  * 探検の時代で増えた出来事：宗教の創始と信条（BELIEF_ADDED）、改宗（CONVERT_CITY。他国が自国の都市を改宗させたものも拾う）、多数派の宗教の変化、専門家の配置（PLACED_WORKER）、得点のための解散（SCORE_DISBAND_UNIT。財宝輸送隊）、火山の噴火（Historian の VOLCANO_ERUPTION）
  * 時代ごとに文明が変わるゲーム（ゲーム6）に対応した（2026-11-03）。Gossip の文明名は時代ごとに変わる（平安日本→戦国日本）ので、自国の行は指導者の名前で見分け、文明名はその時代の区切りに出てくるものを使う。前は「指導者＋最初の時代の文明」で見分けていたので、探検の時代の自国の行をほとんど取りこぼしていた。文明が変わらないゲーム5の記録と、ゲーム6の古代の記録は、直したあとも同じ出力になることを確かめた
  * 前の時代の都市と同じ名前の都市を建てることがある（ゲーム6の鎌倉 (64,34) と (55,16)）。名前が重なる都市は「鎌倉（シベリア）」のように建てた大陸の名前を付け、Gossip の行は座標がいちばん近いほうの都市とみなす。購入（CityPurchase.csv）には座標がないので、同じターンに同じものを建てた都市とみなす
  * ゲーム6の探検の時代で増えた出来事：川の氾濫（Historian の RIVER_FLOODED）、固有の施設の置き換え（UNIQUE_IMPROVEMENT_REPLACED）、居住地の不安（Gossip の CITY_UNREST。施設の名前が一緒に出る）、自国が負けた建設競争（Gossip の LOST_WONDER_RACE が自国の行に出る。このとき Winning City には自国の首都の名前が入っていて当てにならないので、同じターンにその遺産を完成させた他国の行から勝った都市を引く）
