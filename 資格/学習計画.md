# 基本情報・応用情報 学習計画

## 各試験の概要

### 基本情報

「IT全般の基礎知識」を問う試験。

* コンピュータ基礎 / OS / ネットワーク / データベース / セキュリティ
* アルゴリズム / プログラミング
* プロジェクトマネジメント / 経営・会計

一番時間がかかるのは**アルゴリズム・擬似言語**の2つ。暗記系は過去問を回せばかなり点が取れる。

試験は**科目A・科目Bの2つ**に分かれている。科目Aはほぼ過去問道場だけでもかなり対応できるが、**科目Bはアルゴリズムや擬似言語を「理解して解く力」が必要**で、単なる暗記では対応しづらい。

### 応用情報

基本情報の知識がある前提で、追加で「実務寄り」の内容になる。

* 設計 / 要件定義 / 性能設計 / セキュリティ設計 / ネットワーク設計 / DB設計
* マネジメント / システム戦略

単なる暗記ではなく「この状況なら何を選ぶべきか」という問題が増える。**午後問題（記述・ケーススタディ）**では、基本情報以上に「理由を説明できる理解」が重要になる。

### 勉強時間の目安（一般）

IT経験・プログラミング経験でかなり変わるため、あくまで目安。

| レベル | IT未経験 | プログラミング経験あり・現役SE |
| --- | ---: | ---: |
| 基本情報技術者 | 150〜200時間 | 50〜100時間 |
| 応用情報技術者 | 200〜300時間（未経験なら300〜500時間になることも） | 100〜200時間 |

## 自分の場合

実務経験（PHP/Laravel、レイヤードアーキテクチャ設計、API設計、Queue、バッチ、VPN管理システム、要件定義〜運用、レビュー経験）は基本情報のレベルを十分超えている。技術そのものより**試験特有の知識・出題形式を埋める勉強**になる。

**苦戦しそうな分野**
* ストラテジ（経営）
* 会計
* 法務
* 午後の記述問題（応用情報）

**有利な分野**
* DB
* ネットワーク
* セキュリティ
* ソフトウェア設計
* 開発プロセス

**勉強時間の目安（自分の場合）**
* 基本情報：40〜70時間程度
* 応用情報：100〜150時間程度

でも十分合格圏を狙えそう。

## 学習方法：過去問道場を中心にする

結論：**過去問道場をメインにして十分合格できる**。定番の学習法で、CBT公開問題や過去問題を多数収録し、分野別・模試形式・学習履歴管理などの機能もある。ただし「過去問道場だけで何も調べない」のはおすすめしない。

### おすすめの配分

1. **過去問道場（80〜90%）** — ランダム出題・分野別出題・模試をひたすら回す
2. **分からなかった所だけ調べる（10〜20%）** — TCP/IP、正規化、キャッシュ、排他制御、ハッシュ法、オブジェクト指向など、解説を読んでも腑に落ちない部分だけ参考書やChatGPTで補う

### 勉強の流れ（繰り返し）

1. 過去問道場で解く
2. 間違えた問題だけ解説を読む
3. まだ分からなければChatGPTに「なぜこの答えになるの？」と聞く
4. 1週間後に同じ問題を解く

### 正答率の目安

| 正答率 | 学習中の目安 | 受験してよいか |
| --- | --- | --- |
| 60% | まだ危険 | — |
| 70% | 合格ライン | 受験してもいい |
| 75〜80% | — | 安定していればかなり安心 |
| 80〜90% | 安定して取れれば安心 | — |
| 85%以上 | 本番でも余裕がある | 余裕を持って合格を狙える |

応用情報でも「過去問道場＋理解不足だけ補強」というスタイルは有効だが、午後問題の演習に時間を割く必要がある。

## 受験スケジュール

### 生活リズムとの整合を取った実際のペース（2026-07-27改定）

当初「7月末〜8月に基本情報を勉強して9月前半に受験、10月に応用情報受験」というラフ案を検討したが、これは暗黙に**1時間/日前後**のペースを前提にしていた。[../現状整理/生活の優先順位.md](../現状整理/生活の優先順位.md)で確定した資格の時間は**曜日を問わず毎日30分固定**（週210分・年182時間）であり、このペースだと上記のラフ案は達成できない（例：9月前半＝今日から約6週間では22.5時間程度にしかならず、基本情報の目安40時間にも届かない）。

**このため、資格の時間は増やさず、受験日を後ろ倒しにする方針とする。**

30分/日を崩さない前提での目安（今日=2026-07-27起点）：

| フェーズ | 必要時間の目安 | 30分/日での所要日数 | 到達目安日 |
| --- | --- | --- | --- |
| 基本情報 学習（低め） | 40時間 | 約80日 | 2026-10-15ごろ |
| 基本情報 学習（余裕を持つ） | 70時間 | 約140日 | 2026-12-14ごろ |
| **基本情報 受験** | 上記いずれかに到達後 | — | **2026年10月後半〜12月ごろ** |
| 応用情報 学習（低め、基本情報合格後） | 100時間 | 約200日 | 2027-05-03ごろ |
| 応用情報 学習（余裕を持つ、基本情報合格後） | 150時間 | 約300日 | 2027-10-10ごろ |
| **応用情報 受験** | 上記いずれかに到達後 | — | **2027年春〜秋ごろ** |

「半年以内に基本情報→応用情報」という当初目標は、30分/日ペースでは現実的ではない（両方で140〜220時間＝約9.5〜14.5か月かかる）。焦って時間を増やすより、このペースを前提に受験日を決める。

### 最初の1週間の進め方

* Day1：過去問道場で100問くらい解く。正答率は気にせず、得意・苦手分野を把握するのが目的
* Day2〜：苦手分野（コンピュータ構成／ネットワーク／データベース／セキュリティ／アルゴリズムなど）を分野別で集中的に解く

### 受験日の決め方

基本情報はCBT方式で、ほぼ年間を通して受験できる。過去問道場の正答率が上記表の目安時間に近づき、かつ安定して75〜80%以上取れるようになった時点で、**その1〜2か月後**を目安に予約する（期限を作ることで勉強が進みやすくなるため）。

### 基本情報合格後

その勢いで応用情報の過去問道場を始める。基本情報で学んだ内容が残っているうちに進める方が効率がいいが、時間配分（毎日30分）自体は変えない。

※具体的な受験日を予約したら、[../デイリー/](../デイリー/)配下の該当月のカレンダーに追加すること。

## 生活リズムとの接続

[../現状整理/生活の優先順位.md](../現状整理/生活の優先順位.md)で決めた「資格：毎日30分固定」の枠（年換算で約182時間/年）を使う想定。上記の目安（基本情報40〜70時間＋応用情報100〜150時間＝合計140〜220時間）だと、毎日30分のペースでは**低めの見積り（140時間）で約9.5か月、余裕を持った見積り（220時間）で約14.5か月**かかる計算（「1年以内」と言い切れるのは低めの見積りの場合のみ）。上記「受験スケジュール」の到達目安日はこの計算に基づく。
